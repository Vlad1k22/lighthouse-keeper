# Совместная работа

## 1. Получить доступ

Каждый участник создаёт или использует свой аккаунт GitHub и сообщает Владу свой логин. Владелец открывает **Settings → Collaborators → Add people** и отправляет приглашение. Получатель должен принять его в GitHub или по письму.

После принятия приглашения у участника будет доступ к чтению и изменению кода, задачам и Pull Request. В личном репозитории владельцем и администратором остаётся Влад. Если репозиторий приватный, без приглашения ссылка не откроет его содержимое; публичный репозиторий можно смотреть по ссылке, но приглашение всё равно нужно для отправки изменений напрямую.

Официальная инструкция: [приглашение участников в личный репозиторий](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository).

## 2. Скачать проект для разработки

В GitHub Desktop выберите **File → Clone repository → URL** и вставьте:

```text
https://github.com/Vlad1k22/lighthouse-keeper.git
```

Либо в терминале с установленным Git:

```bash
git clone https://github.com/Vlad1k22/lighthouse-keeper.git
```

Откройте `project.godot` в Godot. Для всей команды используем одну версию: **Godot 4.7.2 Stable**, обычный вариант с GDScript.

## 3. Работать в отдельной ветке

Перед началом нажмите **Fetch origin / Pull origin** в GitHub Desktop. Создайте ветку с понятным названием, например `feature/inventory`, `feature/day-night` или `art/lighthouse`.

Договоритесь, какой файл меняет каждый участник. Особенно важно не редактировать одновременно одну презентацию, Word-документ или одну сцену: такие изменения сложнее объединять.

## 4. Сохранить и отправить изменения

Проверьте запуск игры клавишей **F5**. В GitHub Desktop посмотрите список изменённых файлов, напишите короткое описание и нажмите **Commit**, затем **Push origin**.

Создайте **Pull Request** в ветку `main`. Напишите, что изменилось и как это проверить. Другой участник может открыть проект, проверить результат и объединить изменения. После объединения команда обновляет `main` через **Pull origin**.

Пример сообщения коммита: `Добавлен подбор древесины`.

## Какие файлы отслеживаются

В Git хранятся исходники `.gd`, сцены `.tscn`, настройки проекта, постоянные `.gd.uid`, изображения и учебные материалы. Папка `.godot` создаётся движком автоматически и исключена через `.gitignore`.

Godot, его кеш, готовые сборки и личные настройки не нужно добавлять в репозиторий. Для новой задачи удобно создать GitHub Issue с описанием результата: например «После нажатия E у дерева в инвентарь добавляется одна единица древесины».
